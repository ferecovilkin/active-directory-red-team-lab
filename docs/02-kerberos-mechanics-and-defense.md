# Phase 02: Kerberos Protocol Exploitation & Defense

## 1. Overview
Kerberos is the primary authentication protocol in Windows Active Directory. Because the Key Distribution Center (KDC) relies on symmetric cryptography using account passwords to encrypt ticket sessions, flaws in account management enable offline password cracking attacks: **AS-REP Roasting** and **Kerberoasting**.

---

## 2. Technical Attack Vectors

### 2.1 AS-REP Roasting (MITRE T1558.004)
* **Pre-condition:** User account has `DONT_REQ_PREAUTH` enabled (`0x400000` in `userAccountControl`).
* **Protocol Flow:**
  1. Client sends `KRB_AS_REQ` without providing an encrypted timestamp.
  2. The KDC generates a `KRB_AS_REP` message containing a Ticket Granting Ticket (TGT) and session data encrypted with the user's password-derived key.
  3. The adversary captures this encrypted blob and cracks the password offline using hash cracking dictionaries without generating logon failure events (Event ID 4625).

### 2.2 Kerberoasting (MITRE T1558.003)
* **Pre-condition:** Any domain user can request a service ticket (`KRB_TGS_REQ`) for any valid Service Principal Name (SPN) registered in the domain.
* **Protocol Flow:**
  1. Client requests a ticket for a service (e.g. `MSSQLSvc/APP01.corp.local`).
  2. KDC issues a Ticket Granting Service (`KRB_TGS_REP`) encrypted with the NTLM hash of the service account linked to that SPN.
  3. If legacy encryption (`RC4-HMAC`, `0x17`) is accepted, the ciphertext is vulnerable to fast GPU-based cracking.

---

## 3. Detection Engineering

### Detection: Kerberoasting (Event ID 4769)
```
Event ID: 4769 (A Kerberos service ticket was requested)
Ticket Options: 0x40810000
Ticket Encryption Type: 0x17 (RC4-HMAC)
Service Name: NOT ending with '$' AND NOT 'krbtgt'
```

### Detection: AS-REP Roasting (Event ID 4768)
```
Event ID: 4768 (A Kerberos authentication ticket (TGT) was requested)
Pre-Authentication Type: 0 (Disabled)
Target User Name: NOT ending with '$'
```

---

## 4. Remediation & Hardening

1. **Enforce Group Managed Service Accounts (gMSA):**
   * Eliminates static passwords for service accounts. Passwords are 128 characters long, randomly generated by the domain controller, and rotated every 30 days automatically.
2. **Deprecate RC4 Forest-Wide:**
   * Configure Group Policy: `Network security: Configure encryption types allowed for Kerberos` to enable only `AES128_HMAC_SHA1` and `AES256_HMAC_SHA1`.
3. **Audit Pre-Authentication:**
   * Run defensive audit scripts to identify and disable `DONT_REQ_PREAUTH` across all accounts.
